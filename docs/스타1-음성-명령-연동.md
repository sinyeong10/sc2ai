# 음성 명령 연동 (외부 STT 보드 → 빌드 어시스턴트) — 2026-11-08

STT 는 다른 보드(회사 엔진)에서 돌리고, 이쪽은 **인식 결과를 받아 명령으로 바꾸는 연동**만 한다. 이 문서는 보드 쪽 담당자가 볼 인터페이스 명세다.

## 구성

```
[마이크] → 회사 STT (다른 보드) ──HTTP 또는 TCP──► bridge/voice/gateway.py (이 PC) ──의도 파일──► bridge/live_run.py (제어 루프) ──TCP──► 게임
```

- 게이트웨이: `py -X utf8 bridge/voice/gateway.py` (기본 HTTP 15810, TCP 15811, 모든 인터페이스에 바인드)
- 제어 루프: `py -X utf8 bridge/live_run.py --backend bwapi-win --intent-file bridge/results/intents.txt` (게이트웨이와 같은 파일)
- 두 프로세스는 같은 PC 에 두고, 보드는 이 PC 의 IP 로 보낸다. 방화벽에서 15810/15811 을 연다. 인증은 없으니 사내망 전제.

## 보드가 보내는 것

**문장(권장).** STT 의 최종 인식 결과 한 문장. 게이트웨이의 규칙 NLU 가 명령으로 바꾼다.

```
POST http://<PC>:15810/text
Content-Type: application/json
{"text": "질럿 세 기", "final": true}
```
`final` 이 `false` 면(부분 결과) 무시하고 `{"ok":true,"ignored":"partial"}` 로 답한다. `text/plain` 본문으로 문장만 보내도 된다.

**구조화된 의도.** 보드 쪽에 NLU(Dialogflow 등)가 있으면 바로 의도를 보낸다. 검증·정규화만 한다.

```
POST http://<PC>:15810/intent
{"intent": "produce", "unit": "zealot", "count": 3}
```

**TCP.** 15811 에 붙어 한 줄에 하나씩 보낸다. 날 문장이거나 위 JSON. 응답도 한 줄 JSON.

## 응답

```
{"ok": true,  "intent": {"intent":"produce","unit":"zealot","count":3,"text":"질럿 세 기"}, "say": "질럿 3"}
{"ok": false, "error": "명령으로 해석되지 않음: '오늘 날씨 어때'", "say": "잘못된 명령이에요"}
```
`say` 는 보드가 TTS 로 읽어 주라고 주는 확인 문장이다. 실패도 들리게 한다(조용히 버리지 않는다). HTTP 상태는 성공 200, 거부 422, 형식 오류 400.

## 의도 스키마 (한 곳: `gateway.py` 의 `INTENT_SCHEMA`)

| intent | 필드 | 범위 | 뜻 |
|---|---|---|---|
| `produce` | `unit`, `count` | unit ∈ zealot, dragoon, high_templar, dark_templar, worker, pylon, gateway, nexus, assimilator, core, citadel, archives; count 1~100 | 생산·건설 목표. 큐에 순서대로 |
| `reserve` | `minerals`, `gas` | 0~10000 | 예비 자원(앞 목표가 끝난 뒤 효력) |
| `worker_target` | `count` | 0~200 | 일꾼 목표(상시) |
| `army` | `op` | attack | 전체 공격 이동 |
| `cancel`, `status`, `rebalance` | | | 큐 비우기 / 상태 / 멀티로 일꾼 이전 |

숫자는 `float()` → 유한성 → 범위 → `int()`. 유닛 이름은 복수형·별칭(zealots, gate, ht, dt, gas, expand …)을 받아 통일한다.

## 한국어 문장 규칙 (`bridge/voice/nlu.py`)

- 생산: `<유닛> <수>(기|개|마리)` 또는 `<수> <유닛>`. 수 없으면 1. 예: "질럿 세 기", "드라군 열 기 뽑아", "다크 템플러 하나", "스무 기 질럿", "멀티 해", "가스 지어".
- 수사: 고유어(한·두·세·네·다섯 … 열·스물·서른), 한자어(일·이·삼 … 십·백·천, "이백오십"), 아라비아 숫자. 띄어쓰기는 무시한다.
- 예비: "미네랄 이백 남겨", "미네랄 삼백 가스 백 예비", "이백 남겨"(미네랄).
- 일꾼 목표: "일꾼 스물넷까지", "프로브 십육까지".
- 제어: "총공격/공격", "취소/그만", "상태", "재분배/옮겨".
- 유닛 별칭: 질럿·질롯, 드라군·드라곤, 템플러·하이템플러, 다크·다템·다크템플러, 프로브·일꾼, 파일런·파일론, 게이트·관문, 가스·어시밀레이터, 코어·사이버네틱스, 성채·아둔·시타델, 아카이브, 멀티·넥서스·확장·앞마당.
- 인식기 오류에 맞춰 별칭을 늘릴 수 있다. STT 가 자주 내는 오인식 표기를 알려 주면 추가한다.

## 시험

- `py -X utf8 bridge/voice/nlu.py "질럿 세 기" ...` 문장 → 의도 확인
- `py -X utf8 bridge/voice/test_gateway.py` HTTP·TCP·거부 경로 시험
- 보드 없이 손으로: `curl -X POST http://127.0.0.1:15810/text -H "Content-Type: application/json" -d "{\"text\":\"질럿 세 기\"}"`
- 오프라인 STT 로 전체 흐름을 보고 싶으면 Vosk 한국어 모델이 `bridge/voice/models/`(git 제외)에 있다. 보드 연동이 되면 쓰지 않는다.

## 열린 질문

- 보드 STT 가 주는 신뢰도(confidence)를 받으면 낮은 값은 되묻기(`say`)로 처리할 수 있다. 필드 이름을 알려 주면 넣는다.
- 한 문장에 명령 둘("질럿 셋 뽑고 멀티 해")은 지금 첫 유닛만 본다. 필요하면 분리 규칙을 넣는다.
- 게이트웨이는 인증이 없다. 사내망 밖으로 열지 않는다.

## 상태 질의 ("지금 명령 뭐 들어갔어?")

보드가 상태를 묻는 문장을 보내면 게이트웨이가 제어 루프의 상태 파일(`bridge/results/live_status.json`, 제어 루프가 틱마다 갱신)을 읽어
`say` 에 한 문장으로 답한다. 의도 파일에는 넣지 않는다(질의이지 명령이 아니다). 보드는 `say` 를 TTS 로 읽는다.

- 인식 표현: "상태", "현황", "지금 뭐 하고 있어", "뭐 만들고 있어", "명령 뭐 들어갔어", "큐", "진행", "어디까지", 또는 `{"intent":"status"}`.
- 응답 예: `"지금 질럿 4 중 2 완료. 남은 명령 질럿, 질럿. 질럿 대기 사유 minerals. 큐에 멀티 1, 예비 미네랄 200. 미네랄 120 가스 30 인구 40 중 49 일꾼 16"`
- 제어 루프가 5초 넘게 상태를 안 쓰면 "제어 루프가 응답하지 않아요". 응답 JSON 의 `status` 필드에 원본 상태 객체도 같이 준다.
