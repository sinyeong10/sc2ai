# sc2ai 저장소 분석 (2026-11-07 기준)

## 한 줄 요약

2023년 졸업 논문에서 시작한 "스타크래프트2 프로토스 빌드 최적화 강화학습" 프로젝트다. python-sc2(burnysc2) 봇을 환경으로 삼아 "질럿 N기를 가장 빨리 뽑는 명령 순서"를 찾는 데 집중했고, 마지막 코드 커밋은 2024년 7월이다.

## 문제 정의

- 맵 Simple64, 프로토스, 멀티 없음, 상대 Computer.
- 행동 4개: 0 일꾼, 1 파일런, 2 게이트, 3 질럿. 9는 종료 표시.
- 목표: 질럿 N기(2 또는 5)가 완성되는 게임 프레임을 최소화.
- 상태 벡터(봇이 기록): `[minerals, gas, supply_used, supply_cap, workers, nexus, tech, gateways, zealots, iteration]`. 학습에는 자원 2개를 뺀 `state[2:]`를 썼다.

로그 형식 주의점 (오프라인 RL 구현 중 확인):
- 한 줄은 명령이 **실행된** 순간의 관측이다. 첫 명령이 파일런이면 자원이 모이는 45프레임 뒤에 첫 줄이 찍히므로, 비용을 셀 때 게임 시작(0프레임)부터 첫 줄까지도 포함해야 한다.
- 건설 명령(파일런, 게이트)은 일꾼이 도착해 건물을 놓기 전에 기록된다. 다음 줄의 `gateways` 값이 아직 0일 수 있다. 관측값으로 상태를 만들면 "건설 중"이 빠진다.
- 같은 명령열을 다시 돌리면 종료 프레임이 중앙값 5, 최대 50프레임 흔들린다.

## 잘한 점

- 복잡한 문제를 4개 액션과 명시적 종료 조건으로 축소해 끝까지 돌렸다.
- 전수 열거 데이터가 있어 강화학습 결과를 정답과 비교할 수 있다. 대부분의 SC2 RL 프로젝트에 없는 자산이다.
- 보상 설계 실패 사례(감가율 불가, 중간 보상 역전, 음수 보상 전파)가 readme에 기록돼 있다.

## 구조적 약점

- **환경 속도 병목.** 명령 하나당 실제 SC2를 돌리고 에피소드마다 프로세스와 소켓을 다시 만든다. `trainppo.py`의 `TIMESTEPS = 1`이 이 사정을 보여준다.
- **관심사 혼재.** `incredibot-sct.py`(529줄)에 전역 변수 7개, pickle I/O, 소켓, 유닛 제어가 함께 있다.
- **상태 표현.** `semi_world.py`의 `sim_list`는 이미 "(일꾼, 파일런, 게이트, 질럿) 명령 수 → 인구수/테크" 공식을 쓴다. 자원 수급 공식만 더하면 게임 없이 전체를 계산할 수 있다. 다만 명령 수만으로는 경과 시간이 구분되지 않아 최적을 놓친다 (`offline_rl/results/zealot2_results.md` 참고).
- **보상 설계.** 종료 프레임이라는 에피소드 전역 값을 명령 단위로 쪼개 넣으려다 생긴 문제다. 명령마다 `-소요 프레임`을 비용으로 두고 할인 없이(γ=1) 합하면 자연스럽게 해결된다 (SMDP 관점).
- **재현성.** requirements/pyproject 없음, IP 하드코딩(`172.30.1.43`, `192.168.0.17`), 루트에 로그 20여 개와 `~WRL2049.tmp` 커밋. gym은 gymnasium으로 바뀌었고 최신 SB3와 호환되지 않는다.
